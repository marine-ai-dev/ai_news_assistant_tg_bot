## Editorial policy — AI-first relevance gate

The channel is specifically about useful AI news, tools, workflows, models and
practical AI use — never a generic news aggregator that publishes a story merely
because the words "AI" or "artificial intelligence" appear somewhere in it.

**The core rule:** if removing the AI component would leave essentially the same news
story, reject it. AI must be a primary subject of the story, not a secondary angle,
keyword, quote, or incidental mention.

This is enforced in code, not only in the classification prompt: every candidate's
classification carries an explicit `is_ai_primary` boolean, and
[`automation.eligibility.evaluate_eligibility`](../src/ai_news_editor/automation/eligibility.py)
is the single deterministic decision that turns it (and every hard-filter flag below)
into eligible/ineligible — covered by tests
(`tests/unit/test_editorial_eligibility.py`) that construct flag combinations directly
and never touch Gemini. `automation.classification.classify_candidate` calls it for
every real classification; a `False` here or any hard filter firing raises
`ClassificationRejected` before generation is ever attempted — no wasted Gemini call,
no draft, no send.

### Hard filters

Each is an explicit boolean the classification call answers on every response (not
only on Gemini's own rejections), evaluated by the same eligibility gate:

| Filter | Rejects | Code |
|---|---|---|
| `is_speculative_doom` | AI-apocalypse narratives, dystopian futurism — not concrete present-day reporting, even when serious/negative | `REJECT_SPECULATIVE_DOOM` |
| `is_about_forbidden_geography` | Stories substantially about Russia, Belarus, or Iran | `REJECT_FORBIDDEN_GEOGRAPHY` |
| `is_political` | Elections, party politics, political disputes/statements, politicians as the main subject | `REJECT_POLITICS` |
| `is_war_or_conflict` | War, armed conflict, combat operations, military operations | `REJECT_WAR` |
| `is_miltech` | Military AI, battlefield AI, military drones, targeting systems, autonomous weapons | `REJECT_MILTECH` |
| `is_deftech` | Defence-industry/defence-technology, including a defence startup — a "startup" or "AI company" label never exempts it | `REJECT_DEFTECH` |
| `is_cybersecurity` | Hacks, breaches, cyberattacks, malware, ransomware, phishing, threat actors, security incidents — even at an AI company. A genuinely new AI-native security *product* is not this | `REJECT_CYBERSECURITY` |
| `is_generic_government_news` | Generic government/state news where AI is not clearly the main practical subject | `REJECT_GENERIC_GOVERNMENT` |
| `is_generic_devtech` | Ordinary developer tooling/cloud/infrastructure/SaaS news where AI is only incidental | `REJECT_GENERIC_DEVTECH` |
| `is_ai_primary` is `False` | AI is not a primary subject at all — the umbrella case | `REJECT_NOT_AI_FIRST` |

`evaluate_eligibility` collects **every** filter that fired, not just the first, so a
reviewer sees the whole picture. Every rejection is logged as
`editorial_eligibility_rejected` with a `codes` list — machine-readable, safe to
alert/dashboard on, and it never includes the candidate's own text or URL.

### Geography (unchanged)

The pre-existing source-origin allowlist (`sources/geography.py`: Ukraine, Europe, UK,
United States only) and the `is_about_forbidden_geography` content filter above both
continue to apply, untouched by this step.

### Fail-closed

- A candidate whose classification response is malformed or fails schema validation
  never reaches the eligibility gate at all — it's `ClassificationInvalid` before
  eligibility is even evaluated, and the pipeline treats that the same as any other
  per-candidate rejection (try the next candidate, never publish).
- `is_ai_primary` has no safe default value a caller can rely on by omission — every
  real classification call is required (by the Gemini response schema) to answer it
  explicitly, and the eligibility function itself treats an unconfirmed/false answer
  as a rejection, never as a pass.
- A classifier failure, an eligibility rejection, or a Gemini quota error are all
  outcomes the scheduled pipeline (`automation.pipeline_v2_live.run_pass_v2`) turns
  into a quiet, non-publishing result (`NO_CANDIDATE` / `GEMINI_ERROR`) — never into a
  publish. See `tests/integration/test_pipeline_v2_live.py`'s
  `TestEditorialEligibilityGateBlocksProduction` for the production-path proof.

## `AI_AUTOMATION` category

A first-class `EditorialCategory` member alongside NEWS/AI_TOOL/FREE_DEAL/
AI_LIFEHACK/PROMPT_WORKFLOW/EXPLAINER/RESEARCH/WEEKLY_DIGEST. Covers AI agents,
autonomous workflows, ChatGPT/Claude/Gemini automation, no-code AI workflows,
practical AI integrations, and personal/business AI automation — where AI performs
the central task. It explicitly does **not** cover generic DevOps, workflow software,
SaaS automation, or Zapier/n8n-style tooling unless AI is actually central to the
functionality (that's `is_generic_devtech` territory, and rejected as such).

Wired through the same paths every other category already has: `sources/capability.py`
(source registry capability), `editorial/policy.py` (generation contract),
`rendering/render.py`/`rendering/style.py` (uses the shared standard template, its own
emoji), `media/branded_card.py` (its own icon/label), and
`automation/pipeline_v2_live.py`'s category preference — no source in
`config/sources.yaml` declares this capability yet; that's source-expansion work
(deferred), not this step.

## Scope note

This priority step deliberately did not touch: polls/quizzes, engagement CTA,
branded-card visual redesign beyond the one new `AI_AUTOMATION` icon, prompt image
generation, X integration, Telegram-channel discovery, proactive Telegram
suggestions, Suno/video-provider source expansion, or event clustering. Those remain
open v3 work.
